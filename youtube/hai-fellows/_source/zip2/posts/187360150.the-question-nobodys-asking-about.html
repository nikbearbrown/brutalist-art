You saw the viral tweet. Maybe you panicked. Maybe you doom-scrolled. Maybe you wondered if your CS degree just became wallpaper.

Let’s start with a different question than the one everyone’s asking.

Everyone asks: “Will AI replace software engineers?”

But that’s the wrong question. It’s like asking in 1985: “Will spreadsheets replace accountants?” The question assumes that if a tool can do the tasks, the profession disappears.

Here’s the question we should be asking: “When AI writes 95% of the code, what becomes more expensive—and why?”

Sit with that for a moment.

The Obvious Answer (And Why It’s Wrong)

You’re thinking: “Well, obviously what becomes expensive is the remaining 5% of code that AI can’t write—the novel algorithms, the cutting-edge stuff.”

Reasonable. Let’s test it.

In July 2025, METR ran a randomized controlled trial. Sixteen experienced open-source developers (average 5 years on their projects), repositories over 1 million lines of code, real issues—not leetcode puzzles.

They gave half the developers advanced AI tools. Cursor Pro, Claude 3.5 Sonnet, the works.

Question: If AI is making programming obsolete, what should we observe?

Expected result: Maybe 2-3x faster? At minimum 25% faster, right?

Actual result: 19.4% slower.

Not “slightly less fast.” Actually slower.

You’re thinking: “Wait, that can’t be right. I feel so much faster when Claude generates code for me.”

Yes. The participants thought so too. Before the trial, they predicted they’d be 24% faster. After completing the tasks, they still believed they’d been 20% faster.

They were wrong by 39 percentage points.

Here’s the question that should make you uncomfortable: If people using AI feel dramatically more productive while being measurably less productive, what does that tell us about where the bottleneck actually is?

The Second Answer (Also Insufficient)

You’re thinking: “Okay, so maybe it’s about code review. More AI code means more reviewing, right?”

Closer. The data shows:

  • Code review time: ↑91%

  • Pull request size: ↑154%

  • Bug rates: ↑9%

But here’s the interesting part: Individual developers are completing 21% more tasks. Pull requests surge by 98%. Code generation time drops 60-80%.

So we’re seeing both massive individual productivity gains and organizational slowdowns.

Question: How can individuals be faster while the organization gets slower?

This is what researchers now call the “Verification Inversion.” The bottleneck migrated. It moved from generation to verification.

But here’s what nobody’s talking about: Why does verification get exponentially harder when the code gets better?

The “Almost-Right” Problem

Let me show you something counterintuitive.

Bad code is easy to spot. If AI generates complete nonsense—wrong API calls, invalid syntax, logical contradictions—you reject it instantly. Cognitive load: minimal.

But what about code that’s 95% correct?

That’s the dangerous zone. Code that:

  • Compiles cleanly

  • Passes basic tests

  • Looks plausible

  • Contains one subtle flaw that will cause a production outage at 2am on a Saturday

Question: Which is harder to debug—code you wrote yourself, or “almost-right” code someone else wrote?

The answer determines everything about the future of this profession.

When you write code, you build a mental model as you go. You understand every tradeoff. You know why you chose approach A over approach B. When something breaks, you know where to look because you lived through the reasoning.

When AI writes code, you get the output without the journey. You must reverse-engineer the logic. You must verify not just that it works for the test case, but that it handles the 47 edge cases you didn’t think to prompt for.

The METR researchers found this: Developers spent so much time gathering context to verify whether AI suggestions adhered to project-specific patterns that it negated the time saved in generation.

This is why senior developers (10+ years) ship 2.5x more AI code than juniors but modify 70-80% of it before commit. They possess the skepticism to recognize subtle logical flaws.

The Question About Cost

Let’s return to our original question with new information:

“When AI writes 95% of the code, what becomes more expensive?”

Not the remaining 5% of code AI can’t write.

The verification of the 95% it can write.

Look at the labor market through this lens:

Roles being compressed:

  • Junior engineers doing CRUD operations

  • Basic API integrations

  • Standard database queries

Roles commanding record salaries:

  • Platform Engineers: $182K-$251K (orchestrating AI agents safely)

  • Cybersecurity Architects: $143K-$400K (defending against AI-amplified attacks)

  • Site Reliability Engineers: $130K-$210K (maintaining systems with AI-generated instability)

Notice the pattern? Every high-growth role has one word in common: responsibility for what breaks.

The Accountability Gap

Here’s where it gets uncomfortable.

Code generation has been automated. Accountability has not.

When an AI-generated authentication bypass causes a data breach, who faces the regulatory consequences?

Not the AI. The engineer who accepted the pull request.

When an AI-generated algorithm discriminates against protected classes, who gets subpoenaed?

Not the model. The human who deployed it.

When an AI-generated deployment script takes down production at 2am, who gets paged?

Not Claude. You.

This is the “Accountability Gap.” And it’s widening:

  • 84% of developers use or plan to use AI tools

  • Only 23% of IT leaders feel confident managing AI governance

  • 92% report AI increases the “blast radius” of bad code

Question: If accountability can’t be automated, and the blast radius is growing, what happens to the value of the humans who own that accountability?

It goes up. Way up.

The Real Transformation

Let me show you what actually changed:

In 2023, a typical senior engineer spent:

  • 70% writing/debugging code

  • 20% in meetings

  • 10% on architecture

In 2026, that same engineer spends:

  • 25% generating/prompting code

  • 35% verifying/reviewing AI output

  • 25% in stakeholder alignment

  • 15% on architecture and system design

The ratio inverted. The nature of the work changed. But the role didn’t disappear—it elevated.

You’re thinking: “But what about junior engineers? That pipeline is definitely disrupted.”

Yes. Employment for developers aged 22-25 declined 20% from its late 2022 peak. That’s real, concerning, and requires educational reform.

But here’s the question: Is that “profession elimination” or “pathway compression”?

The ladder got steeper. The bottom rungs—routine implementation work—got automated. But the top rungs now pay premiums for judgment, architecture, and accountability ownership.

The Falsifiable Prediction

Let’s test the viral claim: “Software engineering will be completely obsolete in 6-12 months.”

If that were true by August 2026, we should observe:

The data shows transformation, not elimination.

Question: Why did the viral narrative spread so effectively if the data contradicts it?

Because it confused capability with obsolescence. “Models can do the tasks” became “the profession is obsolete.” That’s like saying “calculators can do arithmetic” means “mathematicians disappeared.”

One did not cause the other.

What Dario Actually Meant

Here’s what Anthropic’s CEO actually said at Davos:

“We might be 6-12 months away from models doing all of what software engineers do end-to-end.”

Notice the careful phrasing. “Models can do the tasks” ≠ “the profession is obsolete.”

He wasn’t predicting job elimination. He was predicting task automation.

And he hedged immediately after: “I think there’s a lot of uncertainty, and it’s easy to see how this could take a few years.”

Even DeepMind’s CEO pushed back: “The full closing of the loop, though, I think, is an unknown. You may need AGI itself to be able to do that in some domains.”

The viral tweet optimized for engagement, not accuracy.

The result? Panic where there should be adaptation. Fear where there should be focus. Resignation where there should be resilience.

The Final Question

So here’s what we learned:

The profession isn’t disappearing. It’s undergoing the same transformation every knowledge profession undergoes when mechanical tasks get automated:

  1. The commodity layer collapses (routine coding)

  2. Value migrates upward (architecture, judgment, accountability)

  3. The skill premium inverts (knowing syntax → knowing what to build)

  4. The profession stratifies (fewer generalists, more specialists)

  5. Education lags (training for yesterday’s jobs)

But here’s the question I want you to take with you:

“If AI can generate all the code but none of the accountability, what does that make you?”

Not obsolete.

The conductor. The owner. The human who decides what the performance should sound like and takes responsibility when the audience boos.

The baton is still in human hands.

The orchestra is just louder now.
