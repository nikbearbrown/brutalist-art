Okay, back up. How do you even train something like this? Don’t language models need millions of examples?

Ah, this is where LoRA comes in—Low-Rank Adaptation. Instead of retraining all 355 million parameters in GPT-2, LoRA only trains 4.3 million new parameters (about 1.2%).

Here’s the math: LoRA adds small matrices to the model’s attention layers. Instead of updating the full weight matrix W, you learn two smaller matrices A and B where:

W_new = W_original + A × B

If W is 1024×1024, but A is 1024×16 and B is 16×1024, you’re only training (1024×16) + (16×1024) = 32,768 parameters instead of 1,048,576. That’s 32× fewer parameters!

Wait, how does that even work? Aren’t you losing information?

You’re betting that the update you need is low-rank—meaning it can be represented by these smaller matrices. Think of it like this: if you’re teaching someone who already speaks English to modernize historical text, you’re making small targeted adjustments, not rewriting their entire understanding of language.

The rank (r=16 in the notebook) controls this trade-off. Higher rank = more expressive updates but more parameters. The notebook tests different ranks (8, 16, 32) and finds that 16 is the sweet spot.

What’s “learning rate” mean?

It controls how much the model updates its weights with each training step. Too small (Config 1) and learning is glacial—you need 100× more steps. Too large and the model “bounces around” and never settles.

The math: after computing the gradient (direction to update), you multiply by learning rate α:

W_new = W_old - α × gradient

If α=0.0001 and gradient=100, you update by 0.01. If α=0.00001 and gradient=100, you update by 0.001—ten times slower!

Why did Config 3 win?

Historical text modernization is a relatively simple transformation for a model that already knows English. You can afford a higher learning rate because you’re making targeted adjustments. The rank=32 gives enough capacity to capture complex patterns without overfitting.

But here’s the kicker: Config 3 had 93% better validation loss than Config 1, but both models had similar inference problems. Because remember—training loss and inference quality are different things!

Dizzy again. How do you actually measure if this thing works?

The notebook implements SEVEN different metrics:

  1. Exact Match - Prediction exactly equals expected (66.67% on test data)

  2. Semantic Similarity - How close is the meaning? (89.74%)

  3. Modernization Success - Did archaic words get modernized? (91.96%)

  4. Length Ratio - Is output reasonable length? (1.0)

  5. Valid Output Rate - Did it generate something coherent? (100%)

  6. BLEU Score - Translation quality metric (0.78)

Why so many?

Because each captures something different! Exact match is too strict—”Why do you weep?” and “Why do you cry?” mean the same thing but don’t match exactly. Semantic similarity is more forgiving but might miss if the model changes meaning. Modernization success checks domain-specific patterns.

You need multiple perspectives to understand model quality.
